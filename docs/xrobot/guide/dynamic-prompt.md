动态变量用于把本次会话的业务资料填入智能体的角色介绍。可以在控制台保存通用的角色和回答规则，再让客户端在建立 WebSocket 连接时通过 `hello.agent_params.custom_replace_prompt` 传入门店、用户或任务资料。

## 配置模板并传入变量

下面以门店客服为例。同一个智能体可以服务不同门店，每次连接传入对应的门店名称和营业时间。

### 1. 在控制台保存角色介绍

在「智能体管理」中打开目标智能体，将以下内容填入「角色介绍」，然后点击「保存配置」。双花括号内的名称就是客户端要传入的变量名。 [智能体配置操作指引](./agent-config.md#role-prompt)

```text
你是门店客服，请用简洁的中文回答门店相关问题。
根据当前门店资料回答。资料缺失时，引导用户联系门店确认。

门店：{{store_name}}
营业时间：{{opening_hours}}
```

### 2. 建立连接并发送 hello

使用已有的地址和鉴权配置连接到目标智能体。连接建立后，将以下 JSON 作为文本消息发送。示例使用 Opus，音频参数请按客户端的实际配置填写。 [WebSocket 协议](../platform/websocket.md)

```json
{
  "type": "hello",
  "version": 1,
  "transport": "websocket",
  "audio_params": {
    "format": "opus",
    "sample_rate": 16000,
    "channels": 1,
    "frame_duration": 60,
    "play_buffer_duration": 1000
  },
  "agent_params": {
    "custom_replace_prompt": {
      "store_name": "滨江店",
      "opening_hours": "每天 10:00 至 21:00"
    }
  }
}
```

角色介绍中的资料部分会替换为以下内容。

```text
门店：滨江店
营业时间：每天 10:00 至 21:00
```

### 3. 验证替换结果

收到服务端的 `hello` 响应后，将示例中的 `session_12345` 替换为响应里的 `session_id`，然后在同一连接中发送测试问题。如果响应未提供 `session_id`，可以省略该字段。也可以通过客户端直接语音提问。

```json
{
  "type": "listen",
  "state": "detect",
  "session_id": "session_12345",
  "text": "请告诉我当前门店的名称和营业时间。"
}
```

回复应提到「滨江店」和「每天 10:00 至 21:00」。再断开连接，将 `store_name` 改为「湖滨店」、`opening_hours` 改为「每天 09:00 至 18:00」，重新连接并发送完整的 `hello`。使用新响应里的 `session_id` 再发同一个问题，验证新值。

## 变量规则

| 项目 | 规则 |
| --- | --- |
| 变量名 | 最长 50 个字符，使用小写英文字母，词间可用单个下划线，对应正则 `^[a-z]+(_[a-z]+)*$`。`room_info_a` 有效，`room_info_1`、`roomInfo` 和 `room__info` 会被忽略。 |
| 占位符 | 写成 <code v-pre>{{room_info_a}}</code>。名称须与 JSON 中的键完全一致，花括号内紧贴变量名。同一个变量可重复引用。 |
| 数量 | 每次连接最多应用 100 个不同的有效变量。超出时保留哪些变量没有顺序保证。 |
| 值与长度 | 使用 JSON 字符串。服务端去掉首尾空白后，保留前 200 个 UTF-8 字节。200 字节约能容纳 66 个常见汉字，实际按编码长度计算。 |
| 缺失与空值 | 省略某个变量时，对应占位符原样保留。显式传入 `""` 时，对应占位符替换为空。 |
| 替换顺序 | 由占位符在模板中的位置决定。相邻占位符直接拼接，换行、空格和标点按模板保留。变量值中的占位符文本原样填入。 |
| 生效范围 | 参数用于当前连接的会话。更换变量值时，重新连接并发送新的 `hello`。修改角色介绍后，先保存配置，再使用新连接验证。 |

控制台的角色介绍可使用平台提供的 <code v-pre>{{assistant_name}}</code> 和 <code v-pre>{{language}}</code>。自定义业务变量请使用独立名称。

## 长内容分段

动态资料超过 200 字节时，按完整字符分成多段，每段控制在 200 个 UTF-8 字节以内。可优先按房型、服务或注意事项拆成独立段落，再为剩余长段使用 `room_info_a`、`room_info_b`、`room_info_c` 等字母后缀。预留的分段用不到时，传空字符串。

例如，2000 个常见汉字按每段最多 66 个切分，约需 31 段。分段与其他变量一起计入每次连接的 100 个变量上限。

在控制台模板中按需要的顺序配置分段，并直接写入段间的换行。

```text
根据当前房型资料回答，资料缺失时引导住客联系前台。

房型资料：
{{room_info_a}}
{{room_info_b}}
{{room_info_c}}
```

将以下对象填入 `hello.agent_params.custom_replace_prompt`。

```json
{
  "room_info_a": "标准双床房配有两张单人床，最多入住两位成人。",
  "room_info_b": "家庭套房设有一间卧室和独立客厅，可向前台咨询加床。",
  "room_info_c": ""
}
```

需要连续拼接时，可写成 <code v-pre>{{room_info_a}}{{room_info_b}}</code>。服务端会移除每段首尾的空格和换行，段间需要空格或换行时，请直接写入模板。

## 常见问题

| 现象 | 排查方法 |
| --- | --- |
| 占位符没有替换 | 核对变量名是否含数字或大写字母、拼写是否与模板一致，以及实际发出的 `hello` 是否包含对应字段。 |
| 动态内容只保留开头 | 检查单个值的 UTF-8 字节数，超过 200 字节的内容需要分段。 |
| 换了变量仍回答旧内容 | 检查控制台配置是否已保存、客户端是否连接到目标智能体，以及新连接是否发出了带新值的 `hello`。 |
| 可选部分仍显示花括号 | 为该占位符显式传入 `""`。模板里与它相邻的固定文字仍会保留。 |
